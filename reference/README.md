# 圆头耄耋桌宠：关键帧参考与素材生成说明

本文档供 Codex 在实现桌宠前读取。用户已经提供若干关键帧，这些图片用于生成六套最终动画，但它们不是已经整理好的运行时素材。

## 1. 核心原则

用户提供的关键帧：

- 大小不一定相同；
- 分辨率不一定相同；
- 宽高比不一定相同；
- 可能带背景，也可能透明；
- 可能来自照片、视频截图、表情包或裁剪图；
- 不一定对应现有六个状态中的任何一个；
- 可能只用于参考脸型、毛色、表情、姿势、视角、动作节奏或画质；
- 同一张关键帧可以同时服务于多个目标状态。

不要根据文件名或目录结构武断地给关键帧分类。必须先观察内容，再选择**特定关键帧**作为某个目标动画的生成参考。

最终运行时仍需要以下六个状态，每个状态严格八帧：

```text
sitting   坐姿
walking   游走
sleeping  睡觉
happy     开心/吃文件
petting   抚摸
hissing   哈气
```

关键帧与六个状态之间不是一一对应关系。Codex 的任务是把非结构化参考图转化为结构化的六套动画。

## 2. 视觉目标

最终桌宠必须保持**现实照片风格**，接近用户提供的真实耄耋图像，而不是卡通重绘。

目标是“有点包浆画质的耄耋桌宠”：

- 看起来像真实猫咪照片或视频截图被抠成桌宠；
- 保持圆头、橘色毛发、飞机耳、暴躁或不耐烦表情等辨识特征；
- 允许轻微模糊、低清缩放感、适度 JPEG 压缩、噪点、旧图色偏和不均匀锐度；
- 可以有轻微抠图边缘或旧表情包 halo，但不能保留完整矩形背景；
- 六套动画必须看起来是同一只猫；
- 画质可以旧，动作和轮廓不能糊到难以识别。

禁止生成：

- 二维卡通、动漫、像素画、矢量插画；
- 3D、塑料玩具、游戏模型风格；
- 高清棚拍、商业宠物广告、过度精修毛发；
- 每帧脸型、毛色、花纹或肢体数量明显变化的素材；
- 为了追求高清而消除参考图原有的表情包和旧图质感。

参考关键帧是角色身份与风格的最高优先级依据。

## 3. 输入目录

将用户原始关键帧视为只读输入：

```text
references/keyframes/
```

不得覆盖、改名、移动或删除用户原始文件。

所有裁剪、抠图、修复、尺寸统一、中间生成和预览文件放在：

```text
artifacts/asset-work/
```

最终程序使用的素材输出到：

```text
src/assets/pet/
├── sitting/00.png ... 07.png
├── walking/00.png ... 07.png
├── sleeping/00.png ... 07.png
├── happy/00.png ... 07.png
├── petting/00.png ... 07.png
└── hissing/00.png ... 07.png
```

## 4. 必须先做的关键帧盘点

在图像生成之前，递归扫描所有关键帧，并生成：

```text
docs/keyframe-inventory.md
```

每张关键帧至少记录：

- 文件路径；
- 原始宽度和高度；
- 文件格式；
- 是否带透明通道；
- 可见的姿势、表情、朝向或动作；
- 更适合作为身份、风格、表情、姿势还是动作参考；
- 可能适用的目标状态；
- 明显的遮挡、模糊、背景或裁切问题。

不得在分析前先把所有输入强制拉伸到统一尺寸。宽高比不同的图片不得直接拉伸变形。

## 5. 选择特定关键帧进行生成

对每个目标状态，先明确选用哪些具体关键帧：

- 身份参考：决定脸型、毛色、耳朵、眼睛和整体辨识度；
- 姿势参考：决定身体角度和重心；
- 动作参考：决定八帧之间的变化；
- 表情参考：决定开心、被摸或哈气时的表情；
- 画质参考：决定包浆、低清、噪点和色偏程度。

用户没有要求某张图必须属于某个状态时，可以自行判断最合理用途。某张图与六个状态都不直接匹配时，仍可以把它用于身份、表情、视角或画质参考，不要直接丢弃。

为每个状态记录实际使用的关键帧，并生成：

```text
docs/asset-generation-report.md
```

报告至少包含：

- 状态名；
- 参考关键帧路径；
- 每张图承担的参考作用；
- 补全或新生成了哪些姿态；
- 为保持身份一致性做了哪些处理；
- 是否存在仍需用户确认的问题。

## 6. 动画生成要求

使用可用的图像生成或图像编辑能力，以选定关键帧为视觉依据，补全六套八帧动画。

生成时：

1. 先确定每个状态的关键姿势，再补中间帧；
2. 尽量采用“基于上一帧的小幅编辑”，不要让八帧分别从零随机生成；
3. 每次只改变动作所需的身体部位，其他部分尽量保持不变；
4. 保持头身比例、脸型、毛色、耳朵和五官稳定；
5. 检查多余肢体、消失尾巴、花纹漂移、背景残留和透明边缘；
6. 保持现实感和包浆画质，不要自动美化成高清卡通猫。

建议动作结构：

- `sitting`：呼吸、眨眼、轻微耳动，循环自然；
- `walking`：完整步态循环，身体重心和四肢变化连续；
- `sleeping`：呼吸起伏、耳朵或尾巴轻动；
- `happy`：看到/吞下文件、满足或开心反应，程序循环至约 2 秒；
- `petting`：头部下压、眯眼或身体轻微顺从，再恢复；
- `hissing`：警觉、飞机耳、张嘴哈气、收回，避免生成成普通打哈欠。

## 7. 最终统一规格

输入关键帧不要求统一规格；只有最终输出需要统一：

- 每个状态八帧；
- `00.png` 至 `07.png`；
- PNG；
- 透明背景；
- 统一 `512 × 512 px` 画布；
- 脚底或身体承重点对齐；
- 角色视觉中心稳定；
- 不直接拉伸角色；
- `walking` 默认朝右，向左由程序水平镜像；
- 不含文字、按钮、对话框或矩形背景。

保留一份生成前的高分辨率中间文件，再输出统一运行图。包浆感应通过受控模糊、压缩、噪点、色偏和旧图边缘实现，而不是靠把图随意缩糊。

## 8. 对话框素材

对话框主体使用 HTML/CSS 构建，避免位图文字在 Windows 高 DPI 和 macOS Retina 下模糊。

视觉上可以使用：

- 低饱和米灰或旧纸色；
- 轻微颗粒、扫描纹理、旧网页质感；
- 克制的边框与阴影；
- 现实包浆风格的耄耋头像。

文字、输入框、发送按钮和错误提示必须保持清晰。包浆只用于角色图片和装饰层，不得降低可读性。

## 9. 无图像生成能力时

如果当前 Codex 环境不能调用图像生成或编辑工具：

1. 不得假装已经生成正式素材；
2. 仍需完成关键帧盘点和参考选择报告；
3. 为六个状态生成明确标注的透明占位素材，使程序可运行；
4. 输出可直接交给图像模型执行的逐状态提示词和参考图清单；
5. 保持最终素材接口不变，后续替换图片时不修改业务代码。

## 10. 完成标准

素材任务完成需同时满足：

- 六个状态均有八帧；
- 每个状态可以单独预览；
- 角色身份跨帧稳定；
- 动作循环或单次播放自然；
- 现实照片风格明确；
- 包浆质感可见但不影响辨识；
- 无明显多肢、脸型漂移或背景残留；
- 原始关键帧未被修改；
- `keyframe-inventory.md` 与 `asset-generation-report.md` 完整；
- Windows 和 macOS 的最终显示尺寸与透明效果可接受。
